## Purpose

定义报告层的展示与复核交互：报告如何呈现、诊断的追踪信息与工具调用摘要如何展示、以及人工采纳与驳回如何在界面上完成与留存。

## ADDED Requirements

### Requirement: 报告展示

报告层 SHALL 展示最近一次诊断的报告内容，并 MUST 标明报告所属的诊断形态、所属项目（项目级时）与生成时间。

没有可展示的报告时 MUST 显示明确的空状态与发起诊断的引导，MUST NOT 显示空白区域。

#### Scenario: 展示报告

- **WHEN** 一次诊断完成并返回报告
- **THEN** 报告层展示报告内容、诊断形态、所属项目与生成时间

#### Scenario: 无报告

- **WHEN** 当前项目尚无诊断报告
- **THEN** 报告层显示空状态与发起诊断的引导

### Requirement: 追踪信息展示

报告层 SHALL 展示本次诊断的追踪标识，并提供可折叠的工具调用摘要区域。

后端尚未返回追踪信息时 MUST 显示为暂不可用，MUST NOT 伪造标识或摘要内容。

#### Scenario: 展示追踪标识

- **WHEN** 报告数据包含追踪标识
- **THEN** 界面展示该标识，可供用户复制

#### Scenario: 展开工具调用摘要

- **WHEN** 用户展开工具调用摘要区域
- **THEN** 界面按顺序展示本次诊断调用的工具及其成败状态

#### Scenario: 追踪信息不可用

- **WHEN** 后端未返回追踪标识与工具调用摘要
- **THEN** 界面显示该区域暂不可用，不展示虚构内容

### Requirement: 采纳与驳回交互

报告层 SHALL 提供采纳与驳回两个操作入口。驳回时 MUST 要求填写原因，原因为空时 MUST NOT 允许提交。

反馈提交后，界面 MUST 展示该报告的反馈结果与反馈时间，并 MUST 禁用重复提交。

#### Scenario: 采纳报告

- **WHEN** 用户点击采纳
- **THEN** 界面记录采纳结果与时间，并将两个操作入口置为已完成状态

#### Scenario: 驳回需填写原因

- **WHEN** 用户点击驳回但未填写原因
- **THEN** 界面阻止提交并提示必须填写原因

#### Scenario: 禁止重复提交

- **WHEN** 某报告已提交过反馈
- **THEN** 界面展示已有反馈结果，不允许再次提交

### Requirement: 反馈提交失败的处理

反馈接口不可用时，界面 MUST 提示提交失败并保留用户已填写的内容，MUST NOT 显示为提交成功。

#### Scenario: 反馈接口不可用

- **WHEN** 用户提交驳回但接口返回错误
- **THEN** 界面提示提交失败，保留已填写的原因供重试

#### Scenario: 重试提交

- **WHEN** 用户在失败后重试提交
- **THEN** 界面以保留的内容再次发起提交
