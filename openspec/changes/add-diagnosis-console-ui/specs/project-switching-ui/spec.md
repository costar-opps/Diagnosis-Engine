## Purpose

定义项目切换的界面行为：项目列表如何呈现、切换如何影响各分区、不可诊断的项目如何标记与限制，以及所选项目在页面之间与刷新之后如何保持。

## ADDED Requirements

### Requirement: 项目列表呈现

界面 SHALL 提供已注册项目的列表，每一项 MUST 展示项目名称与可诊断状态；存在活跃异常时 MUST 有可辨识的标记。

项目列表为空时 MUST 显示明确的空状态说明，MUST NOT 显示空白区域。

#### Scenario: 展示项目列表

- **WHEN** 项目列表加载成功
- **THEN** 界面按项列出各项目名称、可诊断状态与异常标记

#### Scenario: 项目列表为空

- **WHEN** 后端返回的项目列表为空
- **THEN** 界面显示空状态说明，提示尚未注册任何项目

### Requirement: 项目切换入口

界面 SHALL 提供至少一个显式的项目切换入口。当存在多个入口时，各入口 MUST 保持选中状态一致。

#### Scenario: 通过切换器选择项目

- **WHEN** 用户在顶部切换器中选择一个项目
- **THEN** 该项目成为当前项目，其他入口同步显示为选中状态

#### Scenario: 通过列表选择项目

- **WHEN** 用户在项目列表中点击一个项目
- **THEN** 该项目成为当前项目，顶部切换器同步更新

### Requirement: 切换后的分区行为

切换项目时，项目层 MUST 重新加载当前项目的数据，报告层 MUST 清空或切换为当前项目的最近报告，平台层 MUST 保持不变。

切换过程中，项目层 MUST 显示加载状态，MUST NOT 继续展示上一个项目的数据。

#### Scenario: 切换时清除旧数据

- **WHEN** 用户从 A 项目切换到 B 项目
- **THEN** 项目层立即进入加载状态，不再展示 A 项目的指标与异常

#### Scenario: 报告层跟随切换

- **WHEN** 用户切换到 B 项目且 B 项目没有历史报告
- **THEN** 报告层显示暂无报告，而不是继续展示 A 项目的报告

### Requirement: 不可诊断项目的处理

项目被标记为不可诊断时，界面 MUST 在列表与切换器中显示该状态及原因，并 MUST 禁用该项目的诊断入口。

#### Scenario: 标记不可诊断

- **WHEN** 某项目返回的可诊断状态为否并附带原因
- **THEN** 界面在该项目上展示不可诊断标记与原因说明

#### Scenario: 禁止发起诊断

- **WHEN** 用户选中一个不可诊断的项目
- **THEN** 一键诊断入口处于禁用状态，并说明不可诊断的原因

### Requirement: 所选项目的保持

当前所选项目 SHALL 在页面刷新后保持。若保持的项目已不在项目列表中，界面 MUST 回退到列表首个可诊断项目，并提示原项目已不可用。

#### Scenario: 刷新后保持选择

- **WHEN** 用户选中某项目后刷新页面
- **THEN** 界面重新进入控制台时仍选中该项目

#### Scenario: 原项目已移除

- **WHEN** 保持的项目不在最新的项目列表中
- **THEN** 界面切换到首个可诊断项目并提示原项目已不可用
