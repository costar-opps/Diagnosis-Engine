## Purpose

定义一组可复现的故障注入场景及其期望诊断结论，作为演示脚本与诊断质量评测的共同基线，确保系统的多项目诊断能力可被反复验证而非依赖偶发表现。

## ADDED Requirements

### Requirement: 场景库的覆盖范围

场景库 SHALL 至少包含八个场景，且 MUST 覆盖以下五类：平台共享资源问题、单项目业务链路问题、变更引入的回归问题、无告警的静默故障、跨项目依赖与资源争用问题。

场景库 MUST 同时包含至少两个以平台级形态为期望结论的场景，与至少四个以项目级形态为期望结论的场景。

#### Scenario: 场景库满足覆盖要求

- **WHEN** 校验场景库
- **THEN** 五类问题均有至少一个场景，且两种诊断形态的场景数量满足下限

### Requirement: 单个场景的定义要素

每个场景 MUST 声明：场景标识与名称、所属类别、注入方式、预期诊断形态、期望的关键证据类型、期望的根因结论要点、以及判定通过的最低要求。

场景 MUST NOT 以自由文本描述期望结论，而 MUST 给出可逐条判定的要点。

#### Scenario: 场景定义完整

- **WHEN** 向场景库添加一个新场景
- **THEN** 系统校验其定义要素齐备，缺项则拒绝纳入

#### Scenario: 期望结论可逐条判定

- **WHEN** 评估某次诊断是否通过某场景
- **THEN** 依据该场景声明的结论要点逐条判定，得到明确的通过或未通过结果

### Requirement: 场景可复现

每个场景 MUST 可通过声明的注入方式重复触发，且在相同注入条件下 MUST 产生一致的可观测现象（指标变化、日志特征、变更事件）。

场景注入 MUST 可撤销，撤销后系统 MUST 恢复到注入前的可观测状态。

#### Scenario: 重复注入现象一致

- **WHEN** 同一场景连续注入两次
- **THEN** 两次产生的指标异常特征与日志错误特征一致

#### Scenario: 注入可撤销

- **WHEN** 撤销某个已注入的场景
- **THEN** 相关指标恢复正常区间，不再产生该场景特征日志

### Requirement: 平台类场景的期望结论

平台类场景的期望结论 MUST 包含：指出具体的资源瓶颈类型、指出占用主体、给出受影响项目范围。

期望结论 MUST NOT 要求系统指向任一项目的具体业务代码位置。

#### Scenario: 主机内存打满场景

- **WHEN** 注入主机内存接近耗尽的场景并触发诊断
- **THEN** 报告以平台级形态给出，指出内存瓶颈、占用主体与受影响项目范围

#### Scenario: 磁盘将满场景

- **WHEN** 注入磁盘空间接近耗尽的场景并触发诊断
- **THEN** 报告指出磁盘瓶颈并提示日志落盘等连带风险

### Requirement: 项目类场景的期望结论

项目类场景的期望结论 MUST 包含：指出出问题的业务环节、引用来自该项目日志的证据、给出处置建议。

涉及变更的场景，期望结论 MUST 包含变更与故障的时间关联；涉及可定位堆栈的场景，期望结论 MUST 包含文件级或方法级代码线索。

#### Scenario: 业务接口超时场景

- **WHEN** 注入某项目接口响应变慢的场景并触发诊断
- **THEN** 报告指出该项目的延迟指标异常，并引用日志定位到慢环节

#### Scenario: 关键业务成功率骤降场景

- **WHEN** 注入某项目关键业务失败率升高的场景并触发诊断
- **THEN** 报告指出关键链路中出问题的具体环节并给出对应处置建议

#### Scenario: 变更后错误尖刺场景

- **WHEN** 注入一次变更事件并随即产生错误尖刺
- **THEN** 报告的时间线体现变更先于故障，且根因判断关联该变更

#### Scenario: 静默故障场景

- **WHEN** 注入只产生错误日志但不触发任何指标告警的场景并发起诊断
- **THEN** 系统仍能基于日志证据识别异常，不因无告警而报告一切正常

### Requirement: 关联类场景的期望结论

跨项目依赖场景的期望结论 MUST 包含：识别出故障源在下游项目、报告中显式标注已扩展查询的项目。

资源争用场景的期望结论 MUST 包含：识别出表面现象出现在某项目但真实原因为共享资源争用、并完成形态切换。

#### Scenario: 下游依赖故障场景

- **WHEN** 注入下游项目故障导致上游项目调用超时的场景，并对上游发起项目级诊断
- **THEN** 报告指出故障源在下游项目，并标注已扩展查询的项目范围

#### Scenario: 资源争用场景

- **WHEN** 注入某项目内存泄漏导致同机其他项目一并变慢的场景
- **THEN** 系统判定为共享资源争用，以平台级结论呈现，并指出占用主体

### Requirement: 场景执行结果可记录

系统 SHALL 支持记录每次场景执行的结果，包含场景标识、执行时间、生成的报告标识与逐条判定结论。

历史执行结果 MUST 可查询与对比，用于观察诊断质量随迭代的变化。

#### Scenario: 记录一次场景执行

- **WHEN** 完成一次场景注入与诊断
- **THEN** 系统记录该次执行的场景标识、报告标识与逐条判定结论

#### Scenario: 对比历史执行

- **WHEN** 查询同一场景的多次历史执行
- **THEN** 系统返回各次的判定结论，可观察通过项的变化
