## Purpose

定义 Agent 执行过程的可观测行为：一次诊断产生哪些可追踪记录、记录必须包含什么信息、如何按追踪标识回放定位问题、以及哪些运行指标需要对外暴露以支撑成本与质量的持续观测。

## ADDED Requirements

### Requirement: 诊断追踪标识

系统 SHALL 为每次诊断分配全局唯一的追踪标识，并在该次诊断产生的全部记录、报告与日志中携带该标识。

#### Scenario: 报告携带追踪标识

- **WHEN** 一次诊断完成并生成报告
- **THEN** 报告中包含该次诊断的追踪标识

#### Scenario: 失败诊断同样可追踪

- **WHEN** 一次诊断因超时或异常中断
- **THEN** 已产生的记录仍保留追踪标识，可据此定位中断位置

### Requirement: 执行轨迹记录

系统 SHALL 记录一次诊断的完整执行轨迹，至少覆盖三类事件：编排节点的进入与退出、LLM 调用、工具调用。

轨迹记录 MUST 保留事件的先后顺序与各自耗时，使执行序列可被完整重建。

#### Scenario: 重建执行序列

- **WHEN** 依据追踪标识查询某次诊断
- **THEN** 系统返回按时间排序的完整事件序列，包含节点流转、LLM 调用与工具调用

#### Scenario: 定位耗时瓶颈

- **WHEN** 某次诊断总耗时异常偏高
- **THEN** 通过轨迹能够识别出耗时集中在哪一类事件

### Requirement: LLM 调用记录内容

每次 LLM 调用的记录 MUST 包含：模型标识、输入与输出 Token 数、耗时、成败状态、重试次数。

提示词与响应正文的留存 SHALL 可配置；关闭时 MUST 仍保留上述结构化字段，MUST NOT 因关闭正文留存而丢失可观测性。

#### Scenario: 记录 Token 消耗

- **WHEN** 一次诊断中发生多次 LLM 调用
- **THEN** 每次调用的输入输出 Token 数均被记录，可汇总出该次诊断的总消耗

#### Scenario: 记录重试

- **WHEN** 某次 LLM 调用失败并重试
- **THEN** 记录中体现重试次数与最终成败状态

#### Scenario: 关闭正文留存

- **WHEN** 配置为不留存提示词正文
- **THEN** 轨迹中不含正文，但模型标识、Token、耗时、成败等字段完整

### Requirement: 工具调用记录内容

每次工具调用的记录 MUST 包含：工具名称、调用参数、成败状态、耗时、返回内容摘要。

调用被服务端校验拒绝时（如越界访问未授权项目），记录 MUST 保留拒绝原因，使模型的错误工具选择可被观测与统计。

#### Scenario: 记录正常调用

- **WHEN** 诊断过程中调用日志查询工具
- **THEN** 记录包含工具名、参数、耗时与返回摘要

#### Scenario: 记录被拒绝的调用

- **WHEN** 模型传入的项目标识与上下文不一致而被拒绝
- **THEN** 记录保留该次调用及拒绝原因，不因失败而丢弃

### Requirement: 运行指标暴露

系统 SHALL 对外暴露诊断相关的运行指标，至少包含：诊断总次数与成败分布、单次诊断耗时、单次工具调用次数、单次 Token 消耗、工具调用失败率。

指标 SHALL 可按诊断形态与项目维度区分，使不同项目的诊断成本与质量可被分别观测。

#### Scenario: 采集诊断耗时

- **WHEN** 监控系统抓取指标端点
- **THEN** 能够获取诊断耗时的分布数据

#### Scenario: 按项目区分指标

- **WHEN** 查询工具调用失败率
- **THEN** 能够按项目维度分别查看，而非仅有全局聚合值

### Requirement: 可观测不影响主流程

轨迹记录与指标采集 MUST NOT 阻塞诊断主流程。记录写入失败时，系统 MUST 记录该失败并继续执行诊断，MUST NOT 因可观测组件异常导致诊断中断。

#### Scenario: 轨迹写入失败

- **WHEN** 轨迹存储不可用
- **THEN** 诊断继续执行并正常产出报告，同时记录可观测组件的失败

#### Scenario: 记录开销受控

- **WHEN** 一次诊断产生大量工具调用
- **THEN** 轨迹记录对总耗时的影响保持在可接受范围内，不随调用次数显著放大
