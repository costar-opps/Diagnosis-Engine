## Purpose

定义诊断与对话过程中的上下文与记忆行为。本能力不采用通用「聊天记忆 / 编码 harness」范式，而落地为诊断域的 **取证驾驭层（Evidence Harness）**：哪些内容可以进入模型上下文、海量工具返回如何在保持可溯源的前提下压缩、Token 预算如何约束长链路排查并驱动报告置信度、以及跨轮次与跨诊断的记忆各自的可见边界。

## ADDED Requirements

### Requirement: 记忆分层与可见边界

系统 SHALL 将记忆划分为三层：会话短期记忆（同一会话内的对话轮次）、诊断轨迹（单次诊断内的推理与取证过程）、长期知识（知识库中的文档与已沉淀经验）。

每层 MUST 有明确的可见边界：诊断轨迹 MUST NOT 跨诊断复用；会话短期记忆 MUST NOT 进入其他会话；长期知识 MUST 通过检索进入上下文而非整体注入。

单次诊断的工作记忆 MUST 以结构化 **证据黑板（Evidence Blackboard）** 承载，而不是把整段对话 transcript 作为工作记忆。每轮装配给模型的上下文 MUST 以「黑板摘要 + 本步工具摘要结果」为主，MUST NOT 默认回放完整工具原文与完整推理过程。

证据黑板至少包含：诊断形态、项目标识或受影响项目列表、活跃告警、已确认证据、未决假设、已失败工具、预算与裁剪记录。黑板中的每条证据 MUST 能指向来源类别与回查定位；未决假设 MUST 标记为开放 / 已支持 / 已否定。

#### Scenario: 诊断轨迹不跨次复用

- **WHEN** 对同一项目连续发起两次诊断
- **THEN** 第二次诊断从空轨迹与空黑板开始，不携带第一次的推理过程

#### Scenario: 会话记忆不跨会话

- **WHEN** 用户在新会话中提问
- **THEN** 上下文中不包含其他会话的对话内容

#### Scenario: 长期知识按需检索

- **WHEN** 诊断需要处置知识
- **THEN** 系统通过检索取回相关文档片段，不将整个知识库注入上下文

#### Scenario: 每轮只注入黑板而非全文

- **WHEN** 诊断已完成多轮工具调用
- **THEN** 下一轮模型上下文包含更新后的黑板摘要与最近一步工具摘要，不包含已被摘要覆盖的早期原始日志正文

### Requirement: 记忆的项目隔离

会话短期记忆 SHALL 记录其关联的项目标识。当会话中切换项目后，系统 MUST NOT 将切换前项目的业务上下文作为当前项目的判断依据。

诊断装配 MUST 按形态实施上下文防火墙：平台级诊断 MUST 以共享资源指标与受影响项目摘要为主，MUST NOT 将单一项目的业务日志作为全平台根因的唯一证据且不标注范围；项目级诊断 MUST 注入当前项目档案的语义摘要，MUST NOT 沿用其他项目的业务链路语义。

会话内切换项目时，系统 MUST 清空黑板上的业务证据区与未决假设，仅在用户显式确认后才允许引用切换前的结论，且引用时 MUST 标注原项目标识。

#### Scenario: 会话内切换项目

- **WHEN** 用户在同一会话中从 A 项目切换到 B 项目并继续提问
- **THEN** 系统基于 B 项目的档案与数据作答，不沿用 A 项目的业务链路语义

#### Scenario: 切换后引用旧结论

- **WHEN** 用户切换项目后追问"刚才那个问题"
- **THEN** 系统明确指出上一轮结论属于另一个项目，并要求确认追问对象

#### Scenario: 平台级不以单项目日志充当全局唯一证据

- **WHEN** 平台级诊断查询到某一项目的业务错误日志
- **THEN** 该日志只能作为「受影响范围」或「资源争用后果」证据，报告必须标注其项目范围，不得在未标注范围的情况下将其写成全平台根因

### Requirement: 工具返回的摘要化

当工具返回的内容超过配置阈值时，系统 MUST 先在服务端摘要再进入模型上下文，MUST NOT 将原始全量内容直接注入，也 MUST NOT 把「先让模型读全量再自行总结」作为压缩手段。

摘要 MUST 采用溯源优先契约：保留可回查定位信息（时间范围、总条数、查询标识或等价 `rawRef`），标明其为摘要结果及被省略的规模，使后续能够回查原始内容。报告引用的日志或指标论断 MUST 能关联到带 `rawRef` 的摘要条目；无法关联的内容 MUST NOT 作为根因证据。

日志摘要 MUST 按错误签名聚合，输出出现次数、时间分布与代表性样本。指标摘要 MUST 按时间窗降采样。未超过阈值的小结果可以直接进入上下文，但仍 MUST 保留来源定位信息。

#### Scenario: 大量日志返回

- **WHEN** 日志查询返回的记录数超过阈值
- **THEN** 进入上下文的是聚合摘要（错误分类、出现次数、时间分布、代表性样本），并标注原始总条数与 `rawRef`

#### Scenario: 摘要可回查

- **WHEN** 报告引用了某条摘要中的错误特征
- **THEN** 能够依据摘要保留的定位信息回查到对应的原始日志记录

#### Scenario: 小结果不摘要

- **WHEN** 工具返回内容未超过阈值
- **THEN** 原始内容直接进入上下文，不做规模压缩，但保留来源定位信息

#### Scenario: 无溯源信息不得作为根因证据

- **WHEN** 模型试图把一条没有 `rawRef` 的历史知识或口头描述写进根因判断
- **THEN** 系统拒绝将其作为根因证据，仅允许进入待确认线索

### Requirement: Token 预算与超限裁剪

系统 SHALL 为单次诊断设置 Token 预算上限，并在装配上下文前估算用量。

预算即将耗尽时，系统 MUST 按优先级裁剪：优先保留当前步骤所需内容、已确立的证据要点与最近的推理步骤；优先丢弃原始正文、早期已被摘要覆盖的中间结果。裁剪 MUST 留痕并写入黑板与报告。

Token 预算在本系统中同时是置信度机器：发生裁剪或因预算终止时，根因置信度 MUST NOT 标为高；预算耗尽且仍无法完成诊断时，系统 MUST 终止并输出已获得的部分结论，同时标注因预算终止与证据不完整，MUST NOT 静默截断后给出完整结论的假象。

#### Scenario: 触发裁剪

- **WHEN** 长链路排查使上下文接近预算上限
- **THEN** 系统裁剪早期原始内容并保留证据要点，诊断继续进行，黑板记录被裁剪的内容类别

#### Scenario: 预算耗尽终止

- **WHEN** 预算耗尽但根因尚未确定
- **THEN** 系统输出部分结论并标注因 Token 预算终止，置信度不得标为高

#### Scenario: 裁剪留痕

- **WHEN** 本次诊断发生过上下文裁剪
- **THEN** 报告的诊断过程中体现发生了裁剪及被裁剪的内容类别

#### Scenario: 裁剪降低置信度上限

- **WHEN** 本次诊断因预算发生过裁剪或提前终止
- **THEN** 服务端将置信度上限限制为中等或以下，即使模型自评为高也不采用

### Requirement: 记忆不得替代取证

系统 MUST NOT 将记忆中的历史结论直接作为当前诊断的事实依据。历史结论只能作为线索提示，当前结论 MUST 由本次取证得到的证据支撑。

诊断轨迹 MUST 在当次诊断结束后封存，默认不进入下一次诊断的黑板。跨次复用的唯一晋升通道 SHALL 为人工采纳后的知识沉淀：经确认发布的长期知识被检索命中时，MUST 标注为历史线索（`historical_clue`），MUST NOT 自动升格为本次根因证据。

#### Scenario: 历史结论作为线索

- **WHEN** 知识库中存在同类故障的历史结论
- **THEN** 系统将其作为排查方向的提示，仍执行本次数据查询以取得证据，并在黑板上标记为 `clue_only`

#### Scenario: 拒绝直接复用历史结论

- **WHEN** 当前故障现象与历史故障相似，但本次取证未获得对应证据
- **THEN** 系统不得直接沿用历史根因，须标注为待确认线索

#### Scenario: 未采纳的轨迹不回流

- **WHEN** 上一次诊断已生成完整轨迹但报告未被采纳
- **THEN** 下一次诊断不得读取该轨迹作为工作记忆或证据

#### Scenario: 采纳知识命中仍需取证

- **WHEN** 检索命中一条已发布的同类处置知识
- **THEN** 系统可据此规划排查步骤，但根因判断仍须绑定本次工具取证得到的带 `rawRef` 证据
