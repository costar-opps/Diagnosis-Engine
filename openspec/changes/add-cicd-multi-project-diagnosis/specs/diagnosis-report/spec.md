## Purpose

定义诊断报告的输出契约：报告必须包含哪些部分、证据如何与结论绑定、置信度如何标注、以及人工采纳或驳回的反馈如何被记录，使报告可复核、可追溯、可作为后续改进的输入。

## ADDED Requirements

### Requirement: 报告的必备组成

每份诊断报告 MUST 包含：报告标识与生成时间、诊断形态、故障概览、多源对齐时间线、证据链、根因判断与置信度、处置建议、本次诊断的工具调用摘要。

项目级报告 MUST 标明所属项目；平台级报告 MUST 标明受影响项目范围。

#### Scenario: 生成项目级报告

- **WHEN** 项目级诊断完成
- **THEN** 报告包含全部必备组成，并标明所属项目

#### Scenario: 生成平台级报告

- **WHEN** 平台级诊断完成
- **THEN** 报告包含全部必备组成，并列出受影响的项目范围

### Requirement: 多源对齐时间线

报告 SHALL 提供按时间排序的事件时间线，将不同来源的事件对齐到统一时间轴，至少覆盖变更事件、指标异常起点、告警触发时刻与诊断发起时刻。

各事件 MUST 标注来源；来源时间精度不一致时 MUST 标注精度或不确定范围，MUST NOT 伪造精确时刻。

#### Scenario: 部署与故障时间对齐

- **WHEN** 某项目在部署后出现错误率上升
- **THEN** 时间线依次呈现部署、指标异常、告警触发与诊断发起，并标明各自来源

#### Scenario: 时间精度不一致

- **WHEN** 变更事件仅精确到分钟而指标精确到秒
- **THEN** 时间线标注该事件的精度限制，不将其呈现为秒级精确时刻

### Requirement: 证据链与结论绑定

报告 SHALL 按类别组织证据链，至少区分指标证据、日志证据、变更证据与代码线索。

根因判断中的每一项论断 MUST 可追溯到证据链中的具体条目；无证据支撑的论断 MUST NOT 出现在根因判断中，如确有必要 MUST 移入"待确认线索"并明确标注为推测。

#### Scenario: 论断可追溯

- **WHEN** 报告断言某次变更导致故障
- **THEN** 该断言关联到证据链中的变更条目与相应的日志或指标条目

#### Scenario: 推测与结论分离

- **WHEN** 系统怀疑某原因但缺少证据
- **THEN** 该内容出现在待确认线索中并标注为推测，不出现在根因判断中

### Requirement: 置信度标注

报告 MUST 为根因判断给出置信度等级，并说明影响置信度的因素。

出现下列情形之一时，置信度 MUST NOT 标为高：关键数据源查询失败、无知识文档支撑、缺少可定位的代码线索、存在多个互斥的候选原因、本次诊断因 Token 预算发生过上下文裁剪或提前终止。

#### Scenario: 证据完整时的高置信度

- **WHEN** 指标、日志、变更、知识文档四类证据齐备且相互印证
- **THEN** 报告可标注高置信度并说明依据

#### Scenario: 日志缺失时降级置信度

- **WHEN** 日志查询失败导致关键证据缺失
- **THEN** 置信度不高于中等，并在报告中说明降级原因

#### Scenario: Token 预算裁剪时降级置信度

- **WHEN** 本次诊断因 Token 预算发生过上下文裁剪或提前终止
- **THEN** 置信度不高于中等，并在诊断过程中说明证据不完整

#### Scenario: 多个互斥候选原因

- **WHEN** 证据同时支持两种互斥的可能原因
- **THEN** 报告并列呈现候选原因并标注低置信度，不擅自选定其一

### Requirement: 处置建议可溯源

报告中的每条处置建议 MUST 标明来源：来自知识文档的 MUST 标明文档出处；无文档来源的 MUST 标注为模型建议并提示需人工确认。

#### Scenario: 建议来自 runbook

- **WHEN** 处置建议取自某份运维文档
- **THEN** 该建议标注对应文档出处

#### Scenario: 建议无文档来源

- **WHEN** 处置建议由模型基于证据自行给出
- **THEN** 该建议标注为模型建议并提示需人工确认

### Requirement: 人工采纳与驳回反馈

系统 SHALL 允许人工对报告作出采纳或驳回，驳回 MUST 支持填写原因。

反馈 MUST 与报告标识一并持久化，且 MUST 记录反馈时间；已产生反馈的报告内容 MUST NOT 被静默改写。

#### Scenario: 采纳报告

- **WHEN** 值班人员确认报告结论正确并点击采纳
- **THEN** 系统记录采纳结果与时间，并与该报告关联保存

#### Scenario: 驳回并填写原因

- **WHEN** 值班人员认为根因判断有误并驳回，填写实际原因
- **THEN** 系统记录驳回结果、原因与时间

#### Scenario: 报告内容不可静默改写

- **WHEN** 一份已被采纳的报告所依赖的数据源后续发生变化
- **THEN** 原报告内容保持不变，如需更新则生成新报告并保留关联

### Requirement: 诊断过程可复核

报告 SHALL 附带本次诊断的工具调用摘要，包含调用的工具、关键参数、成败状态与总耗时，并提供唯一的诊断追踪标识。

#### Scenario: 查看工具调用摘要

- **WHEN** 用户展开报告中的诊断过程
- **THEN** 系统展示本次诊断调用的工具序列、成败状态与总耗时

#### Scenario: 通过追踪标识定位

- **WHEN** 用户使用报告中的追踪标识查询
- **THEN** 系统能定位到该次诊断的完整执行记录
