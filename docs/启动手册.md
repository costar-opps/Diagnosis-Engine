# Diagnosis-Engine 启动手册（手把手版）

> 本文只讲 **怎么启动**。关电脑怎么停服务请看：[项目启停指南.md](./项目启停指南.md)

---

## 0. 先搞清楚：你要打开几个窗口？

启动完整功能（含 **AI Ops**）时，需要在 **3 个 PowerShell 窗口** 里分别跑命令，**外加 Docker Desktop**：

```
┌─────────────────────────────────────────────────────────────┐
│  ① Docker Desktop（开始菜单打开，等左下角 Running）          │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│  窗口 A          │  │  窗口 B          │  │  窗口 C          │
│  Milvus          │  │  MCP 日志服务    │  │  Java 后端       │
│  + Prometheus    │  │  端口 3000       │  │  端口 9900       │
│  跑完可最小化    │  │  ⚠️ 不能关窗口   │  │  ⚠️ 不能关窗口   │
└──────────────────┘  └──────────────────┘  └──────────────────┘
                              ↓
                    浏览器打开 http://localhost:9900
```

| 窗口 | 作用 | 能不能关 |
|------|------|----------|
| Docker Desktop | 跑 Milvus 向量库 | 关 Docker = Milvus 停 |
| 窗口 A | 启动 Milvus + Prometheus | 命令跑完后可最小化 |
| 窗口 B | MCP（AI Ops 查 CLS 日志） | **不能关**，关了 AI Ops 查日志会失败 |
| 窗口 C | Spring Boot 主程序 | **不能关**，关了网页打不开 |

## 1. 项目路径

先 `git clone` 本仓库，再进入仓库根目录。下文命令都相对于该目录；在资源管理器打开该文件夹后，地址栏输入 `powershell` 最省事。

---

## 2. 在哪里输入命令？（打开 PowerShell）

任选一种方式：

**方式 1（推荐）**
1. 按键盘 `Win + X`
2. 点击 **「终端」** 或 **「Windows PowerShell」**

**方式 2**
1. 按 `Win + R`，输入 `powershell`，回车

**方式 3**
1. 在资源管理器打开克隆下来的 `Diagnosis-Engine` 文件夹
2. 地址栏输入 `powershell` 回车（会在当前目录打开 PowerShell）

每开一个新窗口，Repeat 一次。**窗口 A、B、C 各需要一个 PowerShell。**

---

## 3. 启动前一次性检查（第一次或很久没开电脑时做）

在 **任意一个 PowerShell** 里，**整段复制粘贴** 执行：

```powershell
cd "."

Write-Host "========== 环境检查 ==========" -ForegroundColor Cyan

# Java
try { java -version 2>&1 | Select-Object -First 1 } catch { Write-Host "❌ 未安装 Java" -ForegroundColor Red }

# Maven
try { mvn -version 2>&1 | Select-Object -First 1 } catch { Write-Host "❌ 未安装 Maven" -ForegroundColor Red }

# Node（MCP 需要）
try { node -v } catch { Write-Host "❌ 未安装 Node.js" -ForegroundColor Red }

# Docker
try { docker -v } catch { Write-Host "❌ 未安装 Docker" -ForegroundColor Red }

# cls.env 是否存在
if (Test-Path ".\cls.env") {
    Write-Host "✅ cls.env 已存在" -ForegroundColor Green
} else {
    Write-Host "❌ 缺少 cls.env，请执行：" -ForegroundColor Red
    Write-Host '   Copy-Item ".\cls.env.example" ".\cls.env"' -ForegroundColor Yellow
    Write-Host "   然后用记事本编辑 cls.env 填写密钥" -ForegroundColor Yellow
}

Write-Host "========== 检查结束 ==========" -ForegroundColor Cyan
```

### 3.1 如果缺少 cls.env

在同一 PowerShell 执行：

```powershell
cd "."
Copy-Item ".\cls.env.example" ".\cls.env"
notepad ".\cls.env"
```

在记事本里填写（不要用引号包值）：

```
DASHSCOPE_API_KEY=你的DashScope密钥
TENCENTCLOUD_SECRET_ID=你的SecretId
TENCENTCLOUD_SECRET_KEY=你的SecretKey
CLS_LOGSET_ID=你的日志集ID
CLS_TOPIC_ID=你的日志主题ID
CLS_TOPIC_NAME=local-monitor
CLS_REGION=ap-guangzhou
CLS_LOG_SHIPPING_ENABLED=true
```

保存关闭记事本。**不要把真实密钥写进 `application.yml`，也不要提交 `cls.env`。**

### 3.2 DashScope 大模型密钥

在 `cls.env` 里填写 `DASHSCOPE_API_KEY`（对话和平台级诊断都要用）。  
仓库里的 `application.yml` 只读取环境变量，没有内置默认 Key。

## 4. 正式启动（按顺序，不要跳步）

---

### 步骤 1：启动 Docker Desktop

| 项目 | 说明 |
|------|------|
| **在哪里做** | Windows **开始菜单** → 搜索 **Docker Desktop** → 点击打开 |
| **做什么** | 等待左下角/托盘图标显示 **Engine running** 或 **Running** |
| **成功标志** | Docker 界面不再转圈，状态为运行中 |
| **大约耗时** | 1～3 分钟 |

Docker 没起来，后面 Milvus 会失败。

---

### 步骤 2：窗口 A — 启动 Milvus + Prometheus

| 项目 | 说明 |
|------|------|
| **在哪里做** | **新开第 1 个 PowerShell 窗口**（窗口 A） |
| **做什么** | 复制下面 **整段** 粘贴回车 |

```powershell
cd "."

Write-Host ">>> 正在启动 Milvus (Docker)..." -ForegroundColor Cyan
docker compose -f vector-database.yml up -d

Write-Host ">>> 等待 Milvus 就绪（约 15 秒）..." -ForegroundColor Cyan
Start-Sleep -Seconds 15

Write-Host ">>> Milvus 容器状态：" -ForegroundColor Cyan
docker compose -f vector-database.yml ps

Write-Host ">>> 正在启动 Prometheus..." -ForegroundColor Cyan
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& ".\scripts\start-prometheus.ps1"

Write-Host ""
Write-Host "========== 窗口 A 任务完成 ==========" -ForegroundColor Green
Write-Host "可最小化本窗口，不要关闭" -ForegroundColor Yellow
Write-Host "验证: 浏览器打开 http://localhost:9090/targets" -ForegroundColor Cyan
```

**成功标志：**

- 看到 `Prometheus 启动成功`
- 浏览器打开 http://localhost:9090/targets ，有一行 `super-biz-agent`，状态 **UP**

**如果 Prometheus 失败：** 看窗口里的红色报错；常见原因是 9090 端口被占用（参考 [项目启停指南.md](./项目启停指南.md) 先停旧进程）。

**如果 Milvus 失败：** 确认 Docker Desktop 已 Running，再执行：

```powershell
cd "."
docker compose -f vector-database.yml down
docker compose -f vector-database.yml up -d
```

---

### 步骤 3：窗口 B — 启动 MCP（CLS 日志查询服务）

| 项目 | 说明 |
|------|------|
| **在哪里做** | **新开第 2 个 PowerShell 窗口**（窗口 B） |
| **做什么** | 复制下面 **整段** 粘贴回车 |
| **重要** | 本窗口会 **一直占着**，出现日志后 **不要关、不要 Ctrl+C** |

```powershell
cd "."
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& ".\scripts\start-mcp.ps1"
```

**成功标志（窗口里出现类似文字）：**

```
正在启动 cls-mcp-server (http://localhost:3000/sse) ...
Started cls-mcp-server in sse transport on port 3000
```

**失败常见原因：**

- 没有 `cls.env` → 回到第 3 节创建
- 3000 端口被占用 → 关掉占用进程后重试

检查 3000 是否起来（可在 **另一个** PowerShell 执行）：

```powershell
Invoke-WebRequest -Uri "http://localhost:3000" -UseBasicParsing -TimeoutSec 3
```

不报错一般就说明 MCP 在跑。

---

### 步骤 4：窗口 C — 启动 Java 后端（主程序）

| 项目 | 说明 |
|------|------|
| **在哪里做** | **新开第 3 个 PowerShell 窗口**（窗口 C） |
| **做什么** | 复制下面 **整段** 粘贴回车 |
| **重要** | 第一次启动会下载 Maven 依赖，可能需要 **5～15 分钟** |
| **重要** | 看到 `Started Main` 或 Tomcat started on port **9900** 之前 **不要关窗口** |

```powershell
cd "."
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& ".\scripts\start-app-with-cls.ps1"
```

**成功标志（窗口末尾类似）：**

```
Started Main in x.xxx seconds
Tomcat started on port 9900 (http)
```

**失败常见原因：**

- **9900 端口被占用** → 在 PowerShell 执行：

```powershell
Get-NetTCPConnection -LocalPort 9900 -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue }
```

然后重新执行步骤 4 的启动命令。

- **Milvus 连不上** → 回到步骤 2 检查 Docker 和 Milvus 容器

---

### 步骤 4 备选：用 IntelliJ IDEA 启动后端（不用窗口 C）

如果你更习惯用 IDE：

| 项目 | 说明 |
|------|------|
| **在哪里做** | IntelliJ IDEA |
| **做什么** | 1. File → Open → 选择文件夹 `.` |
| | 2. 找到 `src/main/java/org/example/Main.java` |
| | 3. 右键 → **Run 'Main'** |
| **注意** | 仍需先完成 **步骤 1～3**（Docker、Milvus、Prometheus、MCP） |
| **CLS 环境变量** | 若 CLS 报错，先在 PowerShell 加载 cls.env 再从 IDE 启动，或在 Run Configuration 里配环境变量 |

IDE 启动前在 PowerShell 加载环境变量（可选）：

```powershell
cd "."
Get-Content ".\cls.env" | ForEach-Object {
    if ($_ -match '^([^#=][^=]*)=(.*)$') {
        [System.Environment]::SetEnvironmentVariable($matches[1].Trim(), $matches[2].Trim(), "Process")
    }
}
```

然后在 **同一个已加载环境变量的终端** 里用 `mvn spring-boot:run` 启动，或在 IDE 里手动配置相同变量。

---

### 步骤 5：验证全部服务是否正常

在 **浏览器** 依次打开（不是 PowerShell）：

| 序号 | 地址 | 预期结果 |
|------|------|----------|
| 1 | http://localhost:9900 | 出现「智能 OnCall 助手」网页 |
| 2 | http://localhost:9900/api/monitoring/status | 返回 JSON，有 `hostMetrics` |
| 3 | http://localhost:9900/api/monitoring/cls-verify | `"success": true` |
| 4 | http://localhost:9090/targets | `super-biz-agent` 为 **UP** |
| 5 | http://localhost:9090/alerts | 能看到告警规则列表 |

或在 PowerShell 一键检查端口：

```powershell
9900, 3000, 9090, 19530 | ForEach-Object {
    $port = $_
    $listening = Get-NetTCPConnection -LocalPort $port -State Listen -ErrorAction SilentlyContinue
    if ($listening) {
        Write-Host "✅ 端口 $port 正在监听" -ForegroundColor Green
    } else {
        Write-Host "❌ 端口 $port 未启动" -ForegroundColor Red
    }
}
```

## 4.1 诊断控制台怎么看

控制台分三层，从上往下依次是：

| 分区 | 内容 | 数据来源 |
|------|------|----------|
| **平台层 · 共享资源** | 宿主机 CPU / 内存 / 磁盘的当前值、告警与趋势 | `GET /api/monitoring/aiops-dashboard`（真实数据） |
| **项目层 · 当前项目** | 该项目的业务指标、活跃异常、最近变更，以及「一键诊断」入口 | `GET /api/diagnosis/projects/{id}/summary`（**占位接口**） |
| **诊断报告** | 报告正文、诊断形态、追踪标识、采纳 / 驳回 | 本地存储，按项目分槽 |

切换项目有两个入口，二者选中态始终一致：左侧栏的 **「被监控项目」** 列表，以及顶部工具栏的下拉框。切换项目只刷新项目层与报告层，**平台层不变**——因为它是全平台共享的。

### 分区角标：判断数据可不可信

界面右上角的角标标明该分区数据的可信度，演示前请确认它符合预期：

| 角标 | 含义 | 处理方式 |
|------|------|----------|
| 无角标 | 真实数据 | 正常使用 |
| **占位** | 后端占位接口返回的固定数据 | 结构可信、数值不可信 |
| **样例** | 接口不可达，用的是 `diagnosis-sample-data.js` 里的本地样例 | 采纳 / 驳回按钮被禁用，不能作为诊断依据 |

### 后端占位接口（多项目能力尚未实现）

项目层的四个端点由 `DiagnosisConsoleController` 提供，只返回固定结构，不接真实数据源：

| 方法 | 路径 | 行为 |
|------|------|------|
| GET | `/api/diagnosis/projects` | 返回静态项目列表，带 `placeholder: true` |
| GET | `/api/diagnosis/projects/{id}/summary` | 已登记项目返回静态概览，未登记返回 404 |
| POST | `/api/diagnosis/diagnoses` | 返回 **501**，界面提示「项目级诊断待后端实现」 |
| POST | `/api/diagnosis/reports/{id}/feedback` | 接收并回显，**不落库** |

所以点击项目层的「一键诊断」目前一定会失败并给出未实现说明，这是预期行为。想看真实报告请用顶部的 **「平台级诊断」**，它走的是既有的 `/api/ai_ops` 链路。

## 5. 启动顺序速查（仅命令，给熟练后用）

```powershell
# ===== 0. 开始菜单打开 Docker Desktop，等 Running =====

# ===== 窗口 A =====
cd "."
docker compose -f vector-database.yml up -d
Start-Sleep -Seconds 15
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# ===== 窗口 B（保持运行）=====
cd "."
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& ".\scripts\start-mcp.ps1"

# ===== 窗口 C（保持运行）=====
cd "."
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& ".\scripts\start-app-with-cls.ps1"

# ===== 浏览器 =====
# http://localhost:9900
```

## 6. 只聊天、不跑 AI Ops 时（最少要开什么？）

如果 **暂时不用 AI Ops**，最少启动：

1. Docker Desktop  
2. Milvus：`docker compose -f vector-database.yml up -d`  
3. 后端：`scripts\start-app-with-cls.ps1`  

可以 **不启动** MCP（窗口 B）和 Prometheus（窗口 A 里 Prometheus 部分），但 **AI Ops 和告警分析将不可用**。

## 7. 启动失败对照表

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 网页打不开 localhost:9900 | 窗口 C 后端没起来 | 看窗口 C 红色报错；释放 9900 端口后重启 |
| AI Ops 报 MCP 连接失败 | 窗口 B 没开或已关 | 重新执行步骤 3，保持窗口不关 |
| AI Ops 报 topic_id 不存在 | cls.env 里 TopicId 错误 | 改 cls.env，重启窗口 C |
| AI Ops 报 Arrearage | DashScope 欠费/Key 无效 | 检查 `cls.env` 中的 `DASHSCOPE_API_KEY` 与账户余额 |
| target DOWN | 后端比 Prometheus 晚启动 | 先等 9900 起来，刷新 http://localhost:9090/targets |
| docker compose 报错 | Docker 没启动 | 先开 Docker Desktop |
| 脚本无法运行 | PowerShell 禁止脚本 | 命令里已含 `Set-ExecutionPolicy -Scope Process Bypass` |
